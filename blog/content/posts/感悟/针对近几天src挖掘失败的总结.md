> [!danger] 血泪史
> 1、永远不要针对一个漏洞来进行挖掘，这样就只会复现别人的步骤
> 2、学习里面的一个原理，要学会进行改造
> 3、AI不是万能的，但是滥用他一定会掏空你的钱包

### ① EDUSRC 学习 / 挖掘方向

|方向|主要目标|重点系统/资产|重点漏洞|优先级|
|---|---|---|---|---|
|**高校门户**|找配置、历史系统、后台|官网、二级学院站、新闻站|信息泄露、后台暴露、文件类、配置错误|★★★☆☆|
|**教务系统**|学生/教师/管理员权限边界|教务、成绩、选课、考试|越权、未授权、信息泄露、业务逻辑|★★★★★|
|**统一身份认证**|认证和权限体系|SSO、CAS、统一认证|认证绕过、权限问题、配置泄露|★★★★★|
|**OA / 办公系统**|高权限业务与接口|OA、审批、流程、通讯录|越权、未授权、业务逻辑、文件类|★★★★★|
|**科研系统**|数据、项目、文件权限|科研、项目管理、成果平台|越权、文件读取、信息泄露|★★★★☆|
|**学生工作系统**|学生数据与业务流程|宿管、奖助、请假、就业|越权、未授权、业务逻辑|★★★★☆|
|**财务/缴费系统**|用户、订单、支付对象|缴费、财务、校园卡|越权、业务逻辑、对象权限|★★★★☆|
|**图书馆系统**|用户、借阅、查询接口|图书馆、检索、座位预约|越权、未授权、信息泄露|★★★☆☆|
|**实验室/设备系统**|管理功能和接口|实验室、资产、设备预约|权限、未授权、文件类|★★★★☆|
|**校内 API / JS**|找隐藏接口和业务入口|`api.*`、前端 JS|未授权、越权、信息泄露|★★★★★|
|**历史/旧系统**|找遗留漏洞|`old`、旧站、旧 IP|已知漏洞、配置错误、未授权|★★★★★|
|**测试/开发资产**|找环境配置问题|`test`、`dev`、`uat`|信息泄露、配置错误、未授权|★★★★☆|
|**第三方厂商系统**|找学校使用的产品|OA、教务、统一认证厂商|产品漏洞、配置问题、权限问题|★★★★☆|

### EDUSRC 的核心路线

```
学校域名
   ↓
子域名 / IP / 历史资产
   ↓
系统分类
   ↓
教务 / OA / SSO / 科研 / 学工 / 文件
   ↓
JS / API
   ↓
未授权
   ↓
越权
   ↓
业务逻辑
   ↓
```

这里真正值得你投入时间的，是：

**教务、OA、SSO、科研、学生工作、文件、历史系统、API。**

不要把大量时间耗在单纯的“学校官网 CVE 扫描”上。

# ② 企业 SRC 学习 / 挖掘方向

企业和 EDU 最大的区别是：

> **企业业务复杂很多，业务逻辑的收益会明显提高。**

|**企业官网**|资产入口|官网、营销站|XSS、信息泄露、后台|★★☆☆☆|

# ④ 你现在最应该怎么学

按照你现在已经有的基础，我不会让你从头学 OWASP。

我会直接分成两条线：

### EDUSRC

```
资产发现
↓
高校系统识别
↓
教务 / OA / SSO / 科研 / 学工
↓
JS/API
↓
未授权
↓
越权
↓
文件
↓
历史系统
↓
业务逻辑
```

### 企业 SRC

```
资产发现
↓
业务识别
↓
用户中心 / API / OA / CRM / ERP
↓
JS/API
↓
认证
↓
权限
↓
越权
↓
订单/支付/营销
↓
业务逻辑
↓
SSO/OAuth
↓
文件/SSRF/供应链
```

### 最后把你的学习优先级压缩成：

**EDUSRC：**

> `资产 → 系统分类 → JS/API → 未授权 → 越权 → 文件 → 历史系统 → 业务逻辑 → CVE`

**企业SRC：**

> `资产 → 业务地图 → JS/API → 认证 → 权限 → 越权 → 业务逻辑 → 文件 → SSRF → SSO/OAuth → CVE`

这会比“SQL 注入、XSS、SSRF、RCE 挨个学”更贴近你真正想做的 SRC。


> [!node] 注意
> 1、目前市面上面的很多的漏洞其实是并不存在的，像springboot这样的，他可能是公司遗忘了这一部分，目前已经很少了
> 2、目前需要去学会去翻js的代码，去进行分析
> 3、学会用AI武装自己，但是不要依赖AI
> 4、要耐得住寂寞，要一个流量包一个流量包的去进行测试，可能就会发现里面很多的东西
